# 积分规则

会员号、事件号和消费引用均为字符串，前导零保留。积分必须正整数，使用Decimal校验后转为整数，不支持小数积分。事件时刻有时区偏移，统一UTC。规则有效窗与积分可用期均为半开区间。
同一时刻先发放，再消费，最后退款；同类按事件编号排序。消费批次按最早到期、最早发放、批次编号依次选择，余额不足时整笔失败。批次在到期时刻立即不可用，不能消费未来发放积分。
退款必须引用同一会员已成功消费，累计退款不得超过原消费。部分退款按原分配的逆序回拨，先回拨最后消耗的批次；未到期恢复，已到期只记过期退款，绝不复活。后续消费使用回拨后的可用余额。
发放积分=可用积分+已消费积分−全部已退款积分+自然到期积分+过期退款积分。已退款包括有效恢复与过期不恢复。失败消费与失败退款均不改余额，移入隔离。
期末时点默认2026-11-03T00:00:00+08:00，未来事件隔离。示例会员00001：100+80发放，消费120，退款30，其中20恢复、10过期；再消费50后剩余30。

## 兑换提醒占用（模块7）

提醒事件复用同一 CSV：`type=REMIND` 为提醒生成，意向积分取 `points`，提醒到期时刻取 `expires`，提醒业务号取 `ref`（事件号 `id` 仍唯一，重试是同提醒号的不同事件号）；`type=REMIND_OFF` 为撤下，`ref` 引用被撤下的提醒号，`points` 允许为 0。同一提醒号相同 `version` 重复出现按幂等重试处理，更小版本号隔离（VERSION_ROLLBACK），更大版本号按改版重新裁决。

提醒占用是独立意向台账，不扣减任何批次 `remaining`，不改变发放/消费/退款/到期数字。模块7在模块4的积分流水（EARN/SPEND/REFUND/EXPIRE）之上推进会员可用余额，活跃提醒按 `(提醒到期, 生成时刻, 提醒号)` 先早后晚分配，占用恒满足 `0≤占用≤意向` 且 `同会员占用合计≤当前可用`。普通 SPEND 永远先落账，再压缩占用（HOLD_SQUEEZED），提醒不会误挡消费；REFUND 仅把恢复到未过期批次的部分回补占用（HOLD_RESTORED），过期退款不复活、不可占用。

裁决：可全额兑现才建立全额占用（可发布）；可用不足只保留参考快照（仅快照·余额不足），占用按可用额封顶；曾被消费挤掉过的提醒标压缩待复核。撤下（REMINDER_CANCELLED）与提醒到期（REMINDER_EXPIRED，半开区间到期即失效）释放全部占用；生成失败事件只进隔离，旧占用保持不变。模块7对账不守恒时相关提醒发布状态置对账拦截，模块8归档一并拒绝。门店页面展示提醒占用量、当前可用/可自由支配余额、释放原因码与发布状态；营销触达与其他权益活动不在范围内。
