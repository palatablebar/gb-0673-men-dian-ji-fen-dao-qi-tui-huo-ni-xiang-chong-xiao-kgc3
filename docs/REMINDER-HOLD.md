# 兑换提醒占用 决策记录（ADR）

## 1. 要裁决的问题

门店希望在会员到店兑换**之前**发出可兑现的兑换提醒；财务不接受把尚未到店的意向
记成已用积分。两种做法：

- A. 提前占用提醒额度（soft hold）；
- B. 只保留参考快照，不占任何额度。

## 2. 裁决规则（按兑换能否兑现 + 普通消费是否被误挡）

| 情形 | 裁决 |
|---|---|
| 提醒时点会员**可用且未过期**积分 ≥ 兑换意向，且占用后普通消费仍可正常落账 | A：建立提醒占用 |
| 可用积分不足以全额兑现（含积分已过期、批次已到期） | B：只保留参考快照，占用 0，发布状态=不可发布 |
| 任何把占用当作真实扣减、可能挡住普通消费的做法 | 否决。SPEND 一律按原 FEFO 规则先落账，占用随后被压缩，消费永不因提醒被拒 |

关键边界：**提醒占用是独立的意向台账，不写入积分批次账，不改变发放/消费/退款/到期
任何财务数字**。会员可动用余额与提醒占用是两个维度：

```
批次可用积分 remaining  =  普通消费可动用积分（财务口径，不因提醒减少）
提醒占用 hold           =  为到店兑换预留的意向额度（不扣 remaining）
提醒后可自由支配        =  remaining − Σhold（仅用于兑换预留展示，不拦截消费）
```

## 3. 生命周期规则

1. **会员先消费**：SPEND 照常落账（不查占用、不被占用挡回）。落账后对该会员的活跃
   提醒做压缩重算，按 `(提醒到期时刻, 生成时刻, 提醒号)` 先早后晚分配，被挤掉的部分
   记原因 `HOLD_SQUEEZED`；压到 0 的提醒降级为参考快照（`SNAPSHOT_DOWNGRADED`）。
2. **会员退货**：REFUND 按原规则逆向回拨（过期部分不复活），随后同序重算，把活跃
   提醒的占用补回到请求额（`HOLD_RESTORED`），退款让批次过期的部分永远不能再被占用。
3. **对账不一致不得发布**：每个提醒校验 `占用 ≤ 请求额`、`占用 ≤ 会员当时可用`、
   `Σ占用 ≤ 会员可用`；不满足则 `RECONCILE_MISMATCH`，发布状态=对账拦截。
4. **生成失败保留旧版占用**：提醒事件校验失败只进隔离区，不触碰任何已有占用；
   全量重放失败时保留上一版批次结果（store 只 INSERT OR IGNORE，不覆盖）。
5. **同提醒重试不新增占用**：同 `提醒号 + 同 version` 的重复事件幂等跳过
   （`RETRY_IDEMPOTENT`）；同提醒号出现更小版本号判为版本回退并隔离
   （`VERSION_ROLLBACK`）；更大版本号视为提醒改版，重新裁决。
6. **撤下释放**：`REMIND_OFF` 撤下提醒，占用归零，原因 `REMINDER_CANCELLED`。
7. **到期释放**：提醒到期时刻（半开区间，到期即失效）未撤下的，占用归零，原因
   `REMINDER_EXPIRED`；积分批次到期同样触发重算，过期积分不能再被占用。
8. **已过期积分不可用**：占用只落在 `expires > 当前时刻` 的批次可用积分上；结算时点
   `as_of` 统一做一次到期清扫。

## 4. 发布状态（门店页面可见）

| 状态 | 含义 |
|---|---|
| `可发布` | 全额占用且对账一致 |
| `仅快照·余额不足` | 可兑现性裁决为否，只保留参考快照 |
| `压缩待复核` | 消费挤掉过占用，当前占用小于请求额 |
| `已撤下` / `已到期` | 终态，额度已释放，附释放原因码 |
| `对账拦截` | 占用与对账结果对不上，禁止发布 |

## 5. 范围外

营销触达（短信/推送/站内信）、优惠券、其他权益活动、真实资金/积分划转均不在本模块；
本模块只产出可复核的占用台账与发布裁决。

## 6. 重放与可复核性

提醒事件（`REMIND` / `REMIND_OFF`）与积分事件同表采信、同一 CSV 快照驱动，模块 8
在模块 1–6 的批次结果上做**确定性事件重放**：同输入 + 同规则版本 ⇒ 同占用结果、同
run_id。所有占用变动写 `hold_ledger`（提醒号、会员、动作、积分、时刻、原因码），
随批次持久化并进入归档证据。
